## Which cohorts actually close the illness/recovery training gap?

### Takeaway

For a future access effort, Homekit2020 is the strongest prospective respiratory-onset candidate and Evidation has the stronger published recovery-oriented sensor intersection. Both are now rejected for the current project timeline and neither is acquired. A newer public malaria release offers 300 people's HR/RHR under CC BY 4.0, but public metadata does **not** establish that its test/onset/recovery labels are included. This bounded search established no newly permitted, held, training-sized cohort with the full required paired labels.

### Inferences

- If access is pursued in a future separately authorized effort, favor Homekit for lab-grounded respiratory onset and Evidation for recovery; neither is a current project acquisition priority. Count wearable × observed-label × follow-up intersection before promising training size. COVID-only model training is especially constrained by Evidation's 41 dense COVID participants.
- Homekit and ILI recruit through Evidation/Achievement in overlapping seasons. Participant overlap is plausible but not established: treat them as potentially overlapping rather than independent external validation until the data owners provide a privacy-preserving cohort-overlap statement. No cross-dataset re-identification attempt is justified.
- Missing surveys, untested days, negative PCR at one time and genuinely symptom-free days are different states. Retrospective event onset/recovery information is outcome metadata; it cannot be a predictor known before the report was submitted.

### Gaps

- No acquired Homekit/ILI/CovIdentify archive, Hachi usable-pair counts, endpoint completeness, within-person censoring audit, or cross-cohort overlap proof. Public schemas do not replace file validation. Registry owner must decide admission and storage before data use.
- Malaria archive contents/test-date linkage/recovery labels were not inspected. The live article's correct identifiers are **31444399** and **jwallukhd**; older PDF/search text dropped a digit/letter and led to 404s. Do not use the broken identifiers or count public HR/RHR metadata as proof of released paired outcomes.
- Search covered the registered cohorts and a bounded set of newer prospective papers, not every possible cohort. No claim of exhaustive nonexistence is made.

### Inferences

- Sleep staging on clinical PSG is a separate target from wearable sleep-quality/alertness or illness prediction. Papers cannot establish transfer through unavailable sensors or labels. Any reported benefit needs the same downstream target, subject split, input availability and baseline.
- PPG-DaLiA can support PPG-to-ECG-reference HR regression, not illness/recovery. Sleep-EDF can support sleep-stage classification with a verified montage adapter, not an acute-illness branch by name alone.

### Gaps

- No model/checkpoint was downloaded or run; no Mac ARM64/GX10 compatibility, memory/runtime, checkpoint checksum or Hachi score is established. Observed code revisions are evidence references, not executed manifests.
- PaPaGei external-checkpoint license scope needs explicit resolution. OSF environment mismatch and SleepFM limited-montage compatibility need concrete probes after admission. Foundation-model training-cohort leakage/overlap is not fully audited.

## What exact work can be proposed without premature admission?

### Takeaway

No new branch is admitted, no probe ran, and no new issue should be opened without SnowyFortress/OliveTower agreement. The following specify a narrow executable contract for a future owner; they are proposals rather than invented working commands.

### Cited Findings

- **TimesFM proposal:** a separately scoped `scripts/experiments/timesfm_physiology_probe.py`, isolated Python/Torch environment and HF cache; pin Apache-2.0 2.5 weights/code revision; consume the *same existing forecast snapshot/splits/target channels/horizon/cutoffs* as the accepted baseline. Use official `TimesFM_2p5_200M_torch.from_pretrained` → `ForecastConfig` → `forecast` API; only observed past physiology, no future measurements or retrospective labels. Emit aggregate MAE/MASE, interval coverage, wall time/peak memory and artifact hashes. Compare baseline/Chronos to TimesFM on identical cases. Subject overlap with training corpora and missingness handling must be recorded. [Official executable API](https://huggingface.co/google/timesfm-2.5-200m-pytorch).
- **PaPaGei proposal:** `scripts/experiments/papagei_ppg_dalia_probe.py`, pinned code and approved weight terms, own CPU environment/cache. Parse admitted raw BVP only; reference bandpass/normalization/windowing and resampling to 125 Hz; load `ResNet1DMoE`/`papagei_s.pt`; freeze encoder; fit a simple head for ECG-reference HR. Whole-person held-out folds; same BVP windows and label availability for handcrafted PPG baseline; report aggregate HR error, missing-window exclusions and runtime. Verify participant/pretraining overlap before independent-test language. [Official inference/preprocessing path](https://github.com/Nokia-Bell-Labs/papagei-foundation-model).
- **PSG proposal:** select one admitted sleep-stage dataset and inventory actual EEG/EOG/EMG/ECG/respiratory channels before model selection. A future `scripts/experiments/psg_embedding_probe.py` would fail if the approved montage cannot be represented, extract frozen embeddings via one pinned SleepFM/OSF encoder, train a stage head and compare against identical-split waveform features. OSF requires its documented 12-channel 64-Hz epochs unless a documented missing-channel path passes; no watch-summary substitution. [OSF input/inference contract](https://huggingface.co/yang-ai-lab/OSF-Base), [SleepFM channel/config contract](https://github.com/zou-group/sleepfm-clinical/blob/main/sleepfm/configs/channel_groups.json).

### Inferences

- Only if a rejected source is later readmitted and acquired under a separately authorized effort, its first data task is a **paired-label feasibility audit**: privately join roster/wearables/surveys/tests, emit sanitized counts by observed endpoint and follow-up, register snapshot checksums, agree split hash and freeze selection/calibration before clinical scoring. Preserve the parent plan outer4/inner3/mintrain4/seed42/activeouter0 and the sealed outer test. The verified parent fold hash is `13dd73b4b3f2b6beabe105c5e577e86e935fa68edfdc117d8e9ebdc7c772fa5e`.
- Malaria may be worth a future registry proposal only after official metadata/schema establishes paired label files. Even with access, pathogen/device/population changes require a separate task claim; no respiratory recovery conclusion follows automatically.

### Gaps

- Registry-owner admission, separately owned script/files, exact dataset/model hashes, environment locks and executable run evidence remain pending. The proposed filenames are not existing scripts; invoking them now would fail.
- Core predictive acceptance remains with its active owners and real-data gates. This research does not close predictive capability issues or weaken their acceptance criteria.
